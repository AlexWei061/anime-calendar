# YUC 历史排期日期补全设计

## 背景

当前全库共有 200 条没有具体北京时间的记录，其中 33 条已经有首播日期，167 条连首播日期也未知。只读核对表明，YUC 历史季度页为一部分未知记录保留了类似 `1/8周三晚间`、`1/8周三深夜` 的原始排期文本；现有历史生成器已经读取同一个 `broadcast` 节点，但只识别“网络配信”日期和总集数，没有利用普通电视排期中的日期与星期。

YUC 目前的 HTTPS 证书会使项目中的 Node `fetch()` 校验失败。仓库历史提交 `b39b97b7a2ffd0bb4bfe7ec82efd1f9467995cf7` 保存了 2020 年至 2026 年 YUC 官方季度页的原始 HTML 快照，可以作为本次回填的不可变输入；不得关闭 TLS 校验或依赖第三方镜像。

## 目标

- 用 YUC 明确写出的首播月日和星期补齐缺失字段。
- 将“日期明确、具体时刻不明”的记录标为 `date-only`。
- 保留 YUC 原始排期文本和字段级来源，确保每次补全都能审计。
- 不把“晚间”“深夜”“早间”“下午”等模糊时段换算成具体 `HH:mm`。
- 不覆盖已经由 AniList 或しょぼいカレンダー提供的精确排期。

本次只做数据生成、来源审计和回归测试，不改变日历页面的显示方式。

## 已核对的可补范围

以当前数据和仓库内 YUC 快照进行只读匹配：

- 167 条记录没有日期和时刻。
- 至少 49 条能通过季度和规范化标题，直接匹配到包含 `M/D周X` 的 YUC 原文。
- 另有 3 条能取得明确的一次性放送或配信日期，但不能据此推断固定周播日。
- 一批记录只有“周X”而没有具体月日，必须继续保持 `unknown`。
- 标题后来发生变化的记录必须逐条对照 YUC 官方当前季度页；不能按卡片序号或页面位置猜测身份。

最终补全数量以生成后的审计结果为准，不为达到数量目标放宽匹配或解析条件。

## 方案选择

### 采用：历史官方快照 + 当前页面复核

- 从历史提交中的 YUC 原始 HTML 读取 `broadcast` 文本。
- 为生成器增加显式的本地 HTML 输入方式；在线抓取仍保留为站点证书恢复后的常规入口。
- 对标题完全匹配失败的候选，只使用 YUC 当前官方页面逐条复核。
- 生成文件保留必要的原始排期文本，不重新提交整套大型 HTML 快照。

该方案不绕过证书校验，能够复用已保存的官方证据，也不会重新增加大量历史原始文件。

### 不采用：恢复全部原始 HTML

虽然最直观，但会重新增加大量已经从当前工作树移除的历史页面文件，不符合项目的精简边界。

### 不采用：关闭 TLS 校验后实时抓取

`NODE_TLS_REJECT_UNAUTHORIZED=0`、`curl -k` 等方式会失去服务器身份校验，不作为数据生成链路的一部分。

## 解析规则

生成器从每张 YUC 作品卡的 `<p class="broadcast">` 中取得经过空白规范化的 `sourceSchedule`。

### 普通周播

仅当文本包含明确的月、日和星期时解析，例如：

- `1/8周三晚间`
- `1/10周五深夜 (半年番)`
- `4/3周五下午`

解析结果：

- 月日转换为完整 ISO 日期；季度开始月份之前的月日归入前一年。
- 星期映射为现有的 `Sun` 至 `Sat`。
- `beijingTime` 保持 `null`。
- `timeStatus` 设为 `date-only`。
- 保存 `premiereDateSource: "YUC"` 和 `scheduleWeekdaySource: "YUC"`。
- 保存 `sourceSchedule`，作为原始证据。

“晚间”“深夜”等词只保留在 `sourceSchedule`，不进入钟点字段。YUC 标注的日期按其中文季度页的日期标签直接采用，不根据模糊时段进行跨日换算。

### 一次性放送和网络配信

当 YUC 明确写出月日，但没有固定星期语义时：

- 只补 `premiereDateBeijing` 和 `premiereDateSource: "YUC"`。
- `scheduleWeekday` 保持 `null`，避免暗示每周重复。
- `beijingTime` 保持 `null`，`timeStatus` 设为 `date-only`。
- 已明确属于网络首播的记录继续保留 `premiereKind: "network"`。
- 不能可靠判断为网络首播的一次性“放送”只保存日期和原文，不新增未经来源支持的类型。

### 不可补记录

以下情况保持 `unknown`：

- 只有 `周X`，没有具体月日。
- 只有“晚间”“深夜”等时段描述。
- `broadcast` 为空。
- 标题匹配不唯一或当前页无法确认身份。
- 日期文本不符合已覆盖格式。

解析失败必须进入审计输出，不能静默忽略或使用季度首日代替。

## 合并优先级与修改边界

- 已有 `beijingTime` 的记录完全不改。
- 已有 AniList 或しょぼいカレンダー日期、星期的记录不因本次回填而覆盖。
- 本次主要补齐没有 AniList 身份映射的历史记录。
- 字段值为 `null` 时不得残留对应的 `beijingTimeSource` 或 `scheduleWeekdaySource`；网络首播覆盖旧字段时同步清理失效来源标记。
- 不修改标题、集数、封面、作品 ID、追番存储、已看记录或页面交互。

## 本地快照输入

生成器接受一个显式的本地 HTML 目录参数。目录中的文件按现有季度配置映射，例如 `2020-winter.html`、`2025-fall.html`。缺失文件时应立即报错并指出季度，不能悄悄回退到在线抓取。

本次执行时，从历史提交将所需文件提取到临时目录，再运行生成器。临时目录不提交；生成结果中的 `sourceUrl` 仍指向对应的 YUC 官方季度页，并用 `sourceSchedule` 保存必要证据。

## 审计输出

生成完成后输出至少以下统计：

- 总记录数。
- `exact`、`verified`、`date-only`、`unknown` 数量。
- 本次由 YUC 补日期和星期的数量。
- 本次只补日期的数量。
- 因缺少月日、空排期、标题未匹配或解析格式未知而仍未补全的数量及记录标识。

审计输出用于人工复核和交付说明，不把未验证候选写入运行时数据。

## 测试与验收

### 解析测试

- `1/8周三晚间` 能解析为日期、星期和原始文本，时刻保持 `null`。
- 跨年标签如 1 月季度中的 `12/31` 使用前一年。
- “网络配信”“网络放送”“一举配信”等明确日期只补日期，不生成固定周播日。
- 只有 `周三`、只有模糊时段或空文本时不生成日期。
- 未覆盖格式出现在审计结果中。

### 合并测试

- 未匹配 AniList、但有 YUC 明确日期和星期的记录变为 `date-only`。
- 已有 AniList 或しょぼい精确排期的记录保持原值和原来源。
- `beijingTime: null` 的记录没有 `beijingTimeSource`。
- 网络首播没有固定周播日时，不保留失效的 `scheduleWeekdaySource`。

### 全库验收

- 所有记录 ID、季度数量和 `catalogCount` 保持不变。
- `unknown` 数量下降，下降量与审计中的成功回填数一致。
- 所有新 `date-only` 记录均有 YUC `sourceUrl`、`sourceSchedule` 和对应字段来源。
- 不出现猜测的具体时刻。
- 运行 `npm run lint -- --ignore-pattern .worktrees` 和 `npm test`。

## 页面边界

普通 `date-only` 记录本次只进入数据与审计层。当前 `dateOnlyEventsForWeek` 只展示网络首播，因此这些普通电视记录不会被塞进带钟点的时间轴，也不会错误显示成“网络配信”。是否增加独立的“日期已知 · 时刻未定”区域属于后续 P1 界面任务，需要单独设计和确认。
