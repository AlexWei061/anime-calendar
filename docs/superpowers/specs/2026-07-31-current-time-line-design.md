# 当前时刻发光标线

## 目标

在桌面周时间轴上为当前北京时间显示一条横跨周一至周日的青粉发光横线，并在左端显示 `HH:MM`。用户在时间轴中能一眼定位当前时刻，现有节目卡仍可正常点击。

## 范围

- 仅在当前显示周包含当前北京时间日期时绘制。
- 时间每分钟刷新一次，使用 `Asia/Shanghai`，不依赖用户本地时区。
- 时间在当前动态时间轴边界内时才显示；不改变 `timelineBoundsForEvents` 的裁切规则，也不额外制造空白高度。
- 00:00 至 04:59 映射到前一天栏的 `24:00` 至 `28:59` 位置，与既有凌晨排期规则一致。
- 仅调整桌面时间轴；移动端继续使用原有单日议程。

## 设计

`lib/calendar.js` 增加一个纯函数：给定北京时间日期、`HH:MM` 和时间轴边界，复用已有午夜布局规则，返回标线的视觉日期和垂直偏移；超出边界时返回 `null`。

`app/page.tsx` 订阅一个按分钟变化的北京时间字符串，基于该纯函数计算标线。每个桌面日期栏渲染同一偏移的装饰性线段，首个日期栏带时间标签，因此视觉上形成一条贯穿全周的标线。非本周、服务端首屏、或当前时间不在可视边界时不渲染。

`app/globals.css` 以现有主题 token 生成 2px 青粉渐变、光晕和时间胶囊；标线使用 `pointer-events: none`，不遮挡节目卡按钮。移动端已经隐藏 `.timeline-grid`，无需新增移动交互。

## 验证

先在 `tests/calendar.test.mjs` 为纯函数写失败断言：正常时刻的偏移、凌晨回退到前一天、以及可视边界外返回 `null`。在 `tests/rendered-html.test.mjs` 断言页面只在本周创建标线、按分钟订阅北京时间、并保留无阻塞的发光样式和现有移动端隐藏规则。

完成后运行 `npm run lint -- --ignore-pattern .worktrees`、`npm test` 和 `git diff --check`，再在浏览器确认当前周有 A 方案的横贯发光线、切换周后隐藏、节目卡仍可点击。
