# 我的番剧概览压缩与进度条设计

## 目标

仅优化 `?page=mine` 的首屏右侧“我的番剧概览”。保留现有樱花主题、季度选择、数据口径、页内搜索、周历、选择番剧区和移动端单日议程；不修改“追番统计”页面、接口、数据库或观看状态。

成功标准：桌面端三项概览不再被左侧标题区拉成大面积留白；整体进度能一眼看出完成比例；窄屏仍保持单列且无横向溢出。

## 版式与内容

- 桌面端继续在 Mine hero 的右侧排列三项指标，保持“本季在追 → 今天待看 → 整体进度”的顺序。
- 指标格改为内容高度而非等高拉伸。前两项仅展示标签和紧凑数字，例如“15 部”“2 集”。
- “整体进度”保持第三格，显示“已看 N / 总集数 集”，并在数字下方显示一条细进度条；进度条以 `personalWatchedEpisodeCount / personalEpisodeCount` 计算。
- 未登录或数据仍在读取时，三项继续显示“读取中”，不渲染误导性的 0% 进度条。
- 已读取但没有追番记录时，整体进度显示既有“还没有追番记录”文案，不渲染进度条。

## 实现边界

- `app/page.tsx` 仅为 Mine hero 增加进度条所需的派生比例和语义化原生 `<progress>` 元素；不更改现有统计、季度、路由、认证或 API 调用。
- `app/globals.css` 仅调整 `.personal-hero-metrics` 的对齐与其 Mine 进度子元素的紧凑样式。颜色、边框和进度条填充只使用现有设计 token（及 token 的 `color-mix`），保持浅色与深色主题一致。
- 小于等于 `860px` 时保留现有单列指标；进度条撑满指标格可用宽度，不改变现有移动端导航、周历或议程规则。
- 进度条需要可访问名称，并将可见文本保留为精确集数，不能只用颜色或百分比表达状态。

## 验证

- 为 Mine hero 的进度条、读取/空记录分支与紧凑指标 CSS 添加或更新 `tests/rendered-html.test.mjs` 源码契约。
- 运行定向 UI 测试、`npm run lint -- --ignore-pattern .worktrees`、`npm test` 和 `git diff --check`。
- 在桌面与 390px 宽度、浅色与深色主题下人工确认：指标不再等高留白、进度条可见、搜索和季度选择不受影响。
