# 我的番剧与追番统计：个人编辑页设计

## 目标

让“我的番剧”和“追番统计”与现有“播出表”的季番编辑页处于同一视觉体系，但不复制其大封面 Hero：

- 我的番剧回答“今天怎么追”，把个人安排和本季度收藏放在最前面。
- 追番统计回答“这一路追到哪”，把总体进度与按季度回顾放在最前面。

播出表、查询页、数据源、账号、追番保存、逐集已看 API 与 URL 状态均不在本次范围内。

## 页面结构

### 我的番剧（`?page=mine`）

使用紧凑的个人页首屏 `personal-hero personal-hero-mine`，取代旧的通用页头和紧随其后的查询框。

1. 眉标“我的番剧”，标题“今天要追什么？”，说明文字强调个人日程。
2. 三个只读摘要格：本季在追（`selectedSeasonAnime.length`）、今天待看（`todayBroadcasts.length`）和整体已看进度（由已存在的 `overallProgress` 汇总，零作品时安全显示）。不新增账户字段或服务端计算。
3. 紧凑查询框继续复用原有 `submitPageSearch`，保留 `role="search"` 和输入名称；只移动位置，不复制表单。
4. 原有“一周放送安排”周历紧跟个人页首屏，保留周翻页、移动端单日议程、详情弹窗和逐集已看控件。
5. 原有“本季度想追什么？”选择器继续保留在周历后，仍采用 `<details>`、原有整表保存语义及登录提示。
6. 季度选择器和来源链接仍保留在个人页首屏；历史季度说明仍只在需要时出现。

### 追番统计（`?page=stats`）

使用 `personal-hero personal-hero-stats`，取代旧的通用页头和页头后的查询框。

1. 眉标“追番档案”，标题“这一路追到哪了？”，说明文字强调观看记录。
2. 摘要格复用现有 `displayedOverallProgressTotals`：在追、已看完、未开始；空状态保持零值，不伪造进度。
3. 紧凑查询框继续复用既有提交逻辑，移动至该页首屏。
4. 现有“今日播出”可折叠区与“总体进度”季度筛选／按季作品卡保留。统计摘要的吸顶行为继续使用 `--site-nav-offset`，不得被顶部导航覆盖。
5. 不引入连看天数、评分、推荐或其他当前数据模型没有的指标。

## 共享视觉与响应式

- `personal-hero` 采用现有浅色／深色 token、樱花粉彩与青绿色点缀；不增加硬编码组件颜色或外部图片。
- 与播出表的季番 Hero 区分：个人页更矮、更偏信息摘要，不使用四封面拼贴。
- 摘要格、查询框和季度控件构成可换行的网格；`<=860px` 变为单列并保持现有移动端导航胶囊、七日选择器和单日议程。
- 键盘语义不改变：按钮、`<details>`、表单标签、原生 `<dialog>` 与焦点恢复保持原状。
- 新增 hover 过渡须被 `prefers-reduced-motion` 关闭；所有文本颜色继续使用双主题 token，并沿用现有对比度测试模式。

## 实现边界

- 主要修改 `app/page.tsx` 与 `app/globals.css`；如需锁定结构或响应式契约，仅更新 `tests/rendered-html.test.mjs`。
- 不重写日历排期、搜索逻辑、统计计算、认证或数据库。
- 保留“播出表”已实现的 `seasonal-hero`，只新增独立个人页样式和有语义的 JSX 区块。

## 验证

- 为新的 mine/stats 首屏写先失败的渲染／源码回归断言：标题、唯一查询框、摘要数据来源、保留的选择器／统计区，以及移动端个人页样式。
- 运行 `npm run lint -- --ignore-pattern .worktrees` 和 `npm test`。
- 在可用的浏览器中检查桌面、`<=860px`、浅色与深色；确认我的番剧周历和统计季度筛选仍可操作。
