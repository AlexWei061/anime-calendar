# 封面性能与连播已看原子写入设计

## 目标

- 首页、日历、统计和查询列表只加载适合缩略展示的封面图集，详情弹窗继续使用高清封面。
- 一张包含多集的连播卡只发起一次写请求，所有单集记录在 D1 中全部成功或全部失败。
- 保留现有 UI、封面图集部署方式、逐集详情按钮、旧版连播记录迁移和数据来源规则。

## 非目标

- 不恢复为每部番剧一个部署静态封面文件。
- 不改变番剧卡片尺寸、主题、日历布局或详情交互。
- 不重构 `app/page.tsx` 的其他状态，也不改认证、追番列表或排期算法。
- 不在本次改动中加入内容哈希文件名或新的缓存策略。

## 方案一：双分辨率封面图集

### 资源形态

每个现有高清图集继续使用 `cover-sheet-NN.webp`：

- 高清单格：600×750。
- 用途：仅详情弹窗中的 `.detail-cover`。

同时生成对应的 `cover-sheet-NN-thumb.webp`：

- 缩略单格：300×375。
- WebP quality 82，保持与高清图集完全相同的列数、行数和坐标。
- 用途：首页、日历、移动议程、统计、查询、追番选择和网络放送卡。

`data/cover-sprites.js` 保持现有映射结构，避免为 1,514 个条目重复写入两条 URL。`coverSpriteFor(coverUrl, variant)` 根据变体返回高清 URL 或由高清 URL 派生的 `-thumb.webp` URL；默认变体为 `thumbnail`。

`CoverArt` 增加可选的 `variant` 属性，默认使用缩略图。只有详情弹窗显式传入 `variant="detail"`。因此首屏 HTML 不再引用高清图集，打开详情时浏览器才请求对应高清图集。

### 生成流程

`scripts/generate-cover-sprites.mjs` 先按现有方式生成 600×750 高清图集，再从同一张高清图集机械缩放出 300×375 缩略图集。这样两套图集的网格坐标必然一致，也不增加新的映射文件。

为当前仓库生成首批缩略图时，直接从已提交的高清图集机械缩放；以后新增或更新封面仍沿用现有命令：

```bash
npm run convert:covers-webp
npm run generate:cover-sprites
```

### 验收

- 所有映射都同时存在高清和缩略资源。
- 缩略图宽高恰好为对应高清图的一半。
- 服务端首页 HTML 中的可见封面全部引用 `-thumb.webp`。
- 详情 `CoverArt` 明确使用高清变体。
- 当前全部缩略图集的总大小不超过 60 MiB，任意单张不超过 2 MiB。
- 桌面与 390px 移动端视觉尺寸、裁切和背景定位不变。

## 方案二：连播已看原子写入

### 请求协议

`PUT /api/anime-episode-views` 接收一次用户操作涉及的规范单集数组：

```json
{
  "watchedEpisodes": [
    { "animeId": "example", "episodeStart": 1, "episode": 1 },
    { "animeId": "example", "episodeStart": 2, "episode": 2 }
  ],
  "watched": true
}
```

约束：

- `watchedEpisodes` 必须包含 1–25 条记录。
- 每条记录继续通过 `validateEpisodeView` 校验，只接受已收录作品的规范单集。
- 重复单集按稳定键去重。
- 25 条上限使一次批量插入最多绑定 100 个 D1 参数。

### 数据库写入

- 标记已看：在一次 `db.batch()` 中执行一条批量插入，使用 `onConflictDoNothing()`。
- 取消已看：在一次 `db.batch()` 中执行该批次所有精确删除语句。
- 任意语句失败时整批失败，不能留下部分已看记录。
- GET 中对合法旧版连播范围记录的展开迁移保持不变。

### 前端数据流

日历连播卡仍通过 `episodeViewUnitsForRange` 展开成单集，但只发送一次 PUT。详情页单集按钮复用同一协议，数组中只有一条记录。

前端继续乐观更新：

1. 本地立即应用整批状态。
2. 单次请求成功后保留状态。
3. 单次请求或原子事务失败时整体回滚。

由于服务器端不再存在部分成功，整体回滚后客户端与数据库保持一致。

### 验收

- 连播卡一次点击只调用一次 `/api/anime-episode-views`。
- 请求体包含展开后的全部规范单集。
- 服务端使用同一次 `db.batch()` 完成整个用户操作。
- 非数组、空数组、超过 25 条、未知番剧或非规范集数返回 400，且不写数据库。
- 单集详情按钮、连播卡、旧记录迁移与现有乐观回滚测试继续通过。

## 测试与验证

按测试驱动顺序实施：

1. 先增加批量校验、单次请求、D1 原子批次和缩略图资源断言，并确认在旧代码上失败。
2. 做最小实现使相关测试通过。
3. 生成缩略图集并检查尺寸与包体阈值。
4. 运行 `npm run lint -- --ignore-pattern .worktrees` 和 `npm test`。
5. 本地以无缓存方式检查首页封面请求体积，并在桌面与 390px 移动端确认视觉不变。
