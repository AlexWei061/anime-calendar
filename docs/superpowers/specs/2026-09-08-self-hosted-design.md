# 自有域名与香港服务器重构

用户目标：盘点并重构整个番剧日历，保留已有功能，适合中国大陆大学生自行部署；用户已选择暂不办理 ICP 备案，因此以香港服务器和自有域名为部署目标。

## 实现边界

- 保留现有界面、主题、860px 移动断点、查询参数页面导航和全部账号/追番/已看/头像功能。
- 保留 27 季、1514 部目录的身份、排期和字段来源，尤其是凌晨放送日、先行多集、时刻未知和旧已看范围迁移。
- 当前工作区未提交的主站和 teach 改动是基线；不恢复已删除教材，不将用户改动当作可清理内容。教学目录独立保留，文档标注其快照与新结构的关系。
- 重构交付代码、配置、迁移工具、备份恢复工具和部署说明；不购买服务器、不修改真实 DNS、不读取或移动线上私人数据、不推送或发布旧 Sites。

## 运行结构

采用现有 Next.js 16 / React 19 / TypeScript 的标准 Node.js 运行方式，移除主站对 vinext、Workers 和 Sites 构建的依赖。采用 Next.js standalone 输出，通过单实例 Docker 容器运行。Caddy 处理 HTTPS 和反向代理，Node 端口仅在容器内部可访问。

SQLite 保存账号、会话、收藏和逐集已看；保留 Drizzle schema 与全部历史 SQL 迁移。使用 Drizzle 官方支持的 better-sqlite3 驱动，不创建自有 ORM 适配层。SQLite 文件与私有头像位于 DATA_DIR（开发默认 storage，生产 /app/storage），独立持久化于宿主机目录。APP_ORIGIN 明确生产站点的 HTTPS 来源，不信任浏览器提供的转发头来决定 Cookie 安全属性。

## 模块边界

- 页面只组织视图；日历、搜索统计、账号、详情、选择面板拆成独立组件。提取共享类型、封面组件、日期显示辅助函数，以及主题/时钟/个人记录副作用。按功能计算和缓存派生结果，避免输入账号字段触发全库日历计算。
- 保留 lib 纯函数作为业务规则唯一来源；不增加状态库，不更换 UI 设计体系。
- API 继续使用现有 URL 与响应结构，集中处理写入来源校验、受限 JSON 读取和无敏感字段错误日志；认证入口限流。身份始终来自会话，写入事务和失败回滚继续有效。
- 私有头像继续经认证 API 读取。存储路径以账号散列和版本构成，版本 URL 必须与返回内容一致；写文件失败或数据库失败不得丢掉旧头像。
- 数据生成冻结已有作品 ID。封面生成可从现有图集恢复缺失输入，成功生成全部输出后才替换映射；不手工重写生成目录或重新下载全部封面。

## 数据迁移与维护

提供幂等迁移命令，新库应用历史迁移；备份包含一致的 SQLite 快照与对应头像，恢复到新目录后再切换。旧 D1 SQL 导出与 R2 头像导出作为用户显式提供的输入导入新目录；保留邮箱、密码哈希、作品 ID、逐集记录与头像版本，旧登录会话不迁移，迁移后重新登录。先验证输入和结果，再让部署配置指向新数据目录，拒绝覆盖已有数据库。

单实例 SQLite 适用于此个人项目；数据库与私有头像不暴露为静态资源，不放进 Docker 镜像或 Git。未来如确有多实例需求再更换数据服务，不预建多后端框架。
