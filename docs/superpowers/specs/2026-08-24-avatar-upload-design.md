# 账号头像上传设计

## 目标

- 已登录用户可以从右上角账号卡片上传、手动裁剪、替换和删除头像。
- 头像按账号持久保存；同一账号在其他设备刷新后显示相同头像。
- 保留当前昵称首字默认头像。没有自定义头像或删除头像后立即回退到默认头像。
- 沿用现有邮箱密码认证、账号卡片、亮暗主题、原生对话框和 Sites 托管结构。

## 非目标

- 不增加公开个人主页、头像图库、社交资料或管理员头像管理。
- 不支持 GIF 动画、HEIC、远程图片 URL 或摄像头拍摄。
- 不改变昵称、邮箱、密码和会话规则。
- 不引入第三方裁剪组件或通用文件上传框架。

## 已确认的用户体验

### 入口与账号卡片

- 当前字母头像改为可点击按钮，右下角显示编辑标记；按钮的可访问名称为“上传头像”或“更换头像”。
- 点击头像后打开本地文件选择器，接受 JPG、PNG 和 WebP。
- 账号卡片继续显示昵称、邮箱、修改密码和退出登录，并在已有自定义头像时增加“删除头像”。
- 点击“删除头像”后显示简短确认，说明删除后将恢复默认字母头像。

### 裁剪窗口

- 选择合法图片后打开原生 `<dialog>` 裁剪窗口。
- 桌面端左侧为方形裁剪区，右侧为圆形头像预览；移动端改为上下布局。
- 用户可以拖动图片、使用方向键微调位置，并通过原生范围滑块缩放。
- 圆形遮罩与最终头像外观一致，但保存结果仍是标准方形图片，页面通过圆形样式展示。
- 窗口提供“重新选择”“取消”和“保存头像”。取消不会上传或改变现有头像。

## 存储与数据模型

### R2 图片存储

`.openai/hosting.json` 新增逻辑 R2 绑定 `AVATARS`。头像图片只保存在该私有对象存储中，不写入 D1 或浏览器存储。

每个账号使用稳定前缀与不可猜测的版本对象键：

```text
avatars/<sha256-normalized-email>/<random-avatar-version>.webp
```

键中不出现明文邮箱。替换头像先写入新版本，账号状态切换成功后再尽力删除旧版本，因此上传失败不会覆盖当前头像。

### D1 账号状态

`users` 表新增可空字段 `avatar_version`：

- `null` 表示使用默认字母头像。
- 非空随机版本表示当前账号有自定义头像，并同时作为 R2 对象版本和浏览器缓存版本。

同时更新 `db/schema.ts` 并通过 `npm run db:generate` 生成迁移，不手写与 schema 不一致的 SQL。

R2 与 D1 不能组成同一事务，因此操作顺序固定：

- 上传：生成新版本并写入 R2，再更新 `avatar_version`。D1 更新失败时删除新对象并继续使用旧版本；更新成功后尽力删除旧对象。
- 删除：先将 `avatar_version` 设为 `null`，再尽力删除原版本对象。D1 更新失败时不删除对象并继续使用旧头像；D1 已清空后，即使对象清理失败，该对象也不可见。

## 服务端接口

新增 `app/api/auth/avatar/route.ts`，提供同一路径的三种方法：

### `GET /api/auth/avatar`

- 先通过 `getSessionUser()` 验证 `ac_session`。
- 账号没有自定义头像时返回 `404`，否则按其当前 `avatar_version` 读取对应对象。
- 从 R2 返回 WebP，设置 `Content-Type: image/webp`、`X-Content-Type-Options: nosniff` 和私有缓存头。
- 不接受邮箱、对象键或其他用户身份参数。

### `PUT /api/auth/avatar`

- 先认证，再读取大小受限的请求体；不能只信任浏览器提交的 `Content-Length`。
- 只接受 `image/webp`，最大 1 MiB，并检查 WebP 文件签名。
- 以新随机版本写入当前账号对象键，随后更新 `avatar_version`，返回新的带版本头像地址。
- 上传和数据库更新任一步失败时返回明确错误，不改变客户端当前显示的旧头像。

### `DELETE /api/auth/avatar`

- 先认证，将当前账号 `avatar_version` 清空；数据库更新成功即返回无头像状态，并尽力删除原版本对象。
- 数据库更新失败时返回错误且不删除原对象，客户端继续显示原头像。

### 当前用户资料

`SessionUser`、登录、注册及 `GET /api/auth/me` 的用户资料增加可空 `avatarUrl`。当 `avatar_version` 非空时，地址为：

```text
/api/auth/avatar?v=<avatar_version>
```

版本参数只负责刷新浏览器缓存。图片接口仍根据当前会话读取当前账号，不能通过版本参数访问其他用户头像。

## 客户端裁剪与状态流

裁剪界面放在独立客户端组件中，账号卡片只负责文件选择、打开裁剪窗口和接收保存结果，避免继续扩大账号卡片 JSX。

1. 浏览器拒绝非 JPG、PNG、WebP 或超过 10 MiB 的原图，并在账号卡片附近显示错误。
2. 合法图片在浏览器内解码；动画格式不在接受范围，因此无需保留动画。
3. 裁剪区根据图片比例计算覆盖圆形遮罩所需的最小缩放，用户只能在不露出空白的范围内拖动和缩放。
4. 保存时用 Canvas 生成 `512×512` WebP。默认质量为 0.88；若结果超过 1 MiB，降低质量重新编码一次，仍超限则提示用户重新选择图片。
5. `PUT` 成功后才更新 `currentUser.avatarUrl` 并关闭裁剪窗口。失败时保留图片、缩放和位置以便重试。
6. 图片加载失败时头像元素回退到昵称首字，不让破损图片占据卡片。
7. 删除成功后将 `avatarUrl` 设为 `null`；删除失败时保留当前头像并显示错误。

拖动使用 Pointer Events，兼容鼠标和触摸；裁剪区域支持方向键微调。范围滑块保留可见标签，关闭裁剪窗口后焦点回到头像按钮。

## 错误与安全边界

- 未登录的读取、上传和删除统一返回 `401`。
- 浏览器不能提交邮箱、R2 键、头像版本或其他身份字段来指定操作对象。
- 原图最大 10 MiB；上传结果最大 1 MiB。客户端限制改善体验，服务端限制才是安全边界。
- 上传期间禁用重复保存；替换成功前继续显示旧头像。
- 不记录图片字节、会话令牌、密码或对象键到客户端错误信息。
- 头像对象保持私有，只能通过同源、会话认证的头像接口读取。

## 测试与验收

按测试驱动顺序实施：

1. 为头像格式、WebP 签名、大小上限和稳定对象键增加失败测试。
2. 为 `GET`、`PUT`、`DELETE` 的未登录拦截、当前账号隔离、上传替换、删除和失败顺序增加回归测试。
3. 为 schema、生成迁移、R2 逻辑绑定以及 `/api/auth/me` 的 `avatarUrl` 增加断言。
4. 为账号卡片入口、删除恢复、裁剪窗口、保存成功后更新和失败重试增加客户端行为测试。
5. 验证拖动、方向键、缩放范围、512×512 输出、焦点恢复和移动端上下布局。
6. 运行 `npm run lint -- --ignore-pattern .worktrees`、`npm test` 和 `git diff --check`。

最终验收标准：

- 登录用户可以上传、裁剪、替换和删除头像。
- 同账号刷新或在另一设备登录后显示同一头像。
- 未登录或其他账号不能读取、替换或删除该头像。
- 上传失败不覆盖旧头像，删除失败不错误回退默认头像。
- 无头像和图片读取失败时都显示昵称首字默认头像。
- 桌面与不大于 860px 的移动端布局均无溢出，并保留键盘和触摸操作。
