2命令速查卡

下面的 npm 命令与 package.json 里的 scripts 逐字一致。都在项目根目录执行；# 后是这条命令在干嘛。开跑前先 node -v 确认版本 ≥ 22.13.0，否则后面会莫名其妙报错。

终端 · 项目根目录（npm 命令）
npm install                              # 第一次克隆后装依赖
npm run dev                              # 本地开发服务器（vinext dev）
npm run typecheck                        # TypeScript 严格类型检查（tsc --noEmit）
npm run build                            # 构建 Worker 生产产物（vinext build）
npm run start                            # 以生产模式启动已构建产物（vinext start）
npm run lint -- --ignore-pattern .worktrees  # ESLint，忽略嵌套 worktree
npm test                                 # 完整测试：typecheck + build + node --test
npm run db:generate                      # 改 schema 后生成 D1 迁移
npm run generate:anilist-pilot           # 拉取 AniList 首播/时刻/集数资料
npm run generate:yuc-history-pilot       # 合并 YUC + AniList + しょぼい，生成历史目录
npm run generate:syoboi-history          # 抓取しょぼい电视排期，生成快照
npm run convert:covers-webp              # 把独立封面无损转成 WebP
npm run generate:cover-sprites           # 打包封面为 4×10 WebP 图集并生成映射
node --test tests/calendar.test.mjs      # 只跑周历/日期算法这一个测试文件
node --test tests/anime-data.test.mjs    # 只跑番剧数据校验这一个测试文件

npm test 不是一条独立脚本，它实际执行 npm run typecheck && npm run build && node --test tests/*.test.mjs——即"类型检查 + 构建 + 全部测试"三步，三步全过才算健康。改动后至少跑 npm run lint -- --ignore-pattern .worktrees 和 npm test 两条。

3报错速查表

报错信息是最有价值的线索：先读报错里给出的"文件:行:列"和关键词，再回来对表。左列是症状，右列是处理动作。

认前缀能猜八成：TSxxxx 是编译期类型错（改代码即消）、RangeError 是运行时数据格式错（改数据）、三位数是 HTTP 状态码（改请求/登录）、ESLint: 是风格错（改写法）。

报错片段 / 症状含义处理
Type 'X' is not assignable to type 'Y'（TS2322）类型不匹配看报错的文件:行:列，改字段类型或补 null 处理。
Property 'x' does not exist on type ...（TS2339）对象上没有这个属性检查拼写或类型定义。
'x' is possibly 'null'（TS18047/18048）strict 模式下没处理 null加 if 判断或用 ?? 兜底。
Cannot find name 'x'（TS2304）没导入 / 没声明补 import。
RangeError: Invalid schedule time排期时间格式不对（如 "9:00" 少了前导 0）数据文件里改成 "09:00"。
RangeError: Invalid ISO date日期不是 YYYY-MM-DD改数据里的日期。
Cloudflare D1 binding `DB` is unavailable本地/部署没配 D1 绑定检查 .openai/hosting.json 的 d1 字段与部署配置。
Unknown anime ID: xxx提交了不在 allAnime 里的番剧 ID数据 id 改动或前端状态过期，刷新重试。
watchEpisodes must contain at most 25 items / animeIds must be an array of stringsAPI 参数校验失败（400）按校验信息改正提交内容。
401 Sign in required未登录或会话过期重新登录；本地 http 与 Secure 属性的关系见第 08 章。
409 该邮箱已注册邮箱已存在换邮箱注册，或直接登录。
500 Unable to ...服务器内部错误（多半是数据库/环境问题）看 wrangler 日志（.wrangler/wrangler.log）。
Cannot find module 'xxx'依赖没装或路径写错npm install；或检查相对路径与扩展名。
node: bad option / engines 警告Node 版本不对项目要求 >=22.13.0，用 node -v 查看。
drizzle-kit 迁移冲突 / checksum 不对手改了已有迁移不手改 drizzle/，重新 npm run db:generate。
ESLint: 'x' is defined but never used未使用的变量/导入删除它。
ESLint 大段格式报错风格不合规跑 lint --fix 前先看差异，避免顺带大改。
Object literal may only specify known properties（TS2353）对象字面量写了不存在的字段名对照类型定义检查字段拼写。
Parameter 'x' implicitly has an 'any' type（TS7006）函数参数没标类型补参数类型标注。
Cannot read properties of undefined (reading 'x')访问了 undefined 的属性加判空或用可选链 ?.。
too many SQL variables / 绑定参数超限单条语句绑定参数超过 D1 上限（100）追番写入按 50 个 ID 分批（每条绑 2 个参数）。
Module not found: Can't resolve 'xxx'构建时找不到模块检查 import 路径与扩展名，或 npm install。
The edge runtime does not support Node.js APIsWorker 边缘环境不支持某些 Node 内置 API换成 Cloudflare 兼容实现（见第 07 章）。
ESLint a11y: Form elements must have labels无障碍标注缺失补 aria-label / id 关联。
Cannot redeclare block-scoped variable 'x'（TS2451）同一作用域重复声明同名变量改名或删除多余的声明。
查报错的通用流程：① 读第一行错误类型（TSxxxx / RangeError / 状态码）→ ② 定位报错里的"文件:行:列" → ③ 对表找处理动作 → ④ 改完只跑最相关的那条命令验证（如单个测试文件），别一上来就跑全量。

改完任何东西，按下面顺序过一遍再交卷。前三条是硬门槛，后五条是项目专属的易漏点。

①

typecheck 通过

npm run typecheck 无报错。

②

lint 通过

npm run lint -- --ignore-pattern .worktrees 无 error。

③

测试全绿

npm test = typecheck + build + node --test。

④

两套主题

亮/暗色各点一遍，颜色都走 token，无硬编码色值。

⑤

移动端 ≤ 860px

缩窄窗口，确认还是单日选择器 + 议程，桌面吸顶已关闭。

⑥

?page= 路由后退

搜索/我的/统计来回切，浏览器前进后退不丢状态。

⑦

catalogCount 一致

每个季度 catalogCount === 该季度 anime.length。

⑧

封面图集已重生成

动过封面后，依次跑 convert:covers-webp 与 generate:cover-sprites。

类比：这套清单就是竞赛里的"交卷前检查"——样例过了不算完，还得手造边界数据、检查数组越界、确认没改坏之前的 AC 题。网站也一样：单点能跑不等于整体没回归。改目录数据时再补一条：保留 *Source 审计标记与数据来源 URL，并更新 season.updatedAt。
附录不是用来背的：它是"用到时来查"的手册。第一次查会陌生，查三次就自然记住了——就像查 C++ 的 STL 函数签名，用多了，不需要刻意记。
