项目全景图：一张地图看懂所有文件

这一章给你整个项目的“地图”。以后无论改什么，第一件事永远是：在地图上找到你要改的地方属于哪一层。

阶段二 · 认识项目 约 25 分钟 前置：第 01～03 章

1大局观：四层结构

整个项目可以切成四层，从上到下：界面层 → 逻辑层 → 数据层 → 服务层。界面层只负责“画”，逻辑层只负责“算”，数据层只负责“记”，服务层只负责“网络和数据库”。

注意箭头的方向：数据（番剧目录）不经过网络——它跟着界面一起打包发布；只有“你的账号、追番、已看”这类个人数据才会通过网络走到 D1 数据库。这个分工是理解整个项目的第一把钥匙。

类比：这就像把一本《节目单》（数据层）复印发到每个观众手里（打包进网站），而每个人“我追了哪些、看到第几集”的笔记（个人数据）存在剧场前台的柜子里（D1）。查节目单不用排队，查自己的笔记才要找前台。

光读这段 import，你就能还原整个页面的工作方式：

反过来，lib/calendar.js 的 import 里没有任何 React、没有 data、没有网络——它是个纯算法模块，可以脱离网页单独测试。这就是为什么它的测试（tests/calendar.test.mjs）能像跑竞赛题一样直接跑。

5两条数据流：排期流与个人数据流

排期流（不发网络请求）

  1. 打包时，data/anime.js 汇总全部季度的番剧目录，allAnime 是全集；
  2. 页面加载后，React 组件带着 activeWeekStart 调用 lib/calendar.js 的 eventsForWeek()；
  3. 纯函数把每部番的“首播日期 + 周几 + 时间 + 集数”展开成这一周的具体事件（第 06 章精讲这个算法）；
  4. 布局函数算出每个事件在时间轴上的位置（哪一格、哪条道）；
  5. React 把它们画成节目卡片，封面从 data/cover-sprites.js 查图集坐标。

个人数据流（走网络 + 数据库）

  1. 页面挂载时 fetch("/api/auth/me") 问“我是谁”，再拉追番与已看；
  2. 用户点“追番”或“已看”，页面乐观更新本地状态（先改界面，失败再回滚），同时 fetch 对应 app/api/ 接口；
  3. 服务器端 route.ts 先 getSessionUser() 认证（读 Cookie，未登录 401），再校验数据、写入 D1；
  4. 数据库只存“哪个邮箱 + 哪些番剧 ID / 哪集已看”，番剧详情永远不存数据库。

6这个项目是怎么跑到网上的

一句话：开发时用 npm run dev 在本地起服务；发布时 npm run build 把代码打包成 dist/，部署到 Cloudflare Worker，数据库用云上的 D1。

  • worker/index.ts 是服务器的入口：所有请求先进这里，图片优化走 /_vinext/image，其余交给 vinext 的 app 路由；
  • .openai/hosting.json 声明逻辑资源：d1: "DB"（数据库绑定名）、r2: "AVATARS"（头像存储）——代码里 getDb() 用的就是 env.DB，两边必须一致；
  • 本地开发时，vite.config.ts 用 wrangler/miniflare 在本地模拟 D1 和 R2，所以不联网也能跑通完整功能（本地数据在 .wrangler/，不要提交）；
  • 发布遵循“先验证、再提交、再部署”的顺序，站点默认私有访问。细节在 第 10 章。

7给你的阅读顺序建议

  1. 先读 data/anime.js 开头 130 行——看懂“一条番剧记录长什么样”（下一章讲）；
  2. 再读 lib/calendar.js——它不长（300 行）而且全是纯函数，是最适合你上手的“算法文件”（第 06 章精讲）；
  3. 然后读 app/page.tsx 的 import 块 + 状态清单 + 任意一个事件处理函数，感受三层协作；
  4. 最后读一个 API（app/api/anime-selections/route.ts，60 行）——后端比前端简单得多。

1.（单选）当周排期事件（某番这周几集、几点播）是在哪里算出来的？

这是项目最重要的分层约定：排期与布局计算全部留在 lib/，app/page.tsx 只负责状态与渲染，D1 只存个人数据。你可以在 Node 里直接 import lib/calendar.js 验证任何日期，完全不用开网页。

2.（多选）下面哪些文件属于“服务器端”，运行在 Cloudflare Worker 里？

lib/ 是纯函数库，被两端共用：页面 import 它在浏览器跑，API 也可能 import 它在服务器跑——所以它必须保持“无环境依赖”。route.ts、db/、worker/ 只活在服务器上。这也解释了为什么 lib/ 里不写任何 fetch/数据库调用。

3.（单选）D1 数据库里存的是什么？

番剧目录是静态数据，打包在网站里随页面一起分发（快、省钱、离线可算）；封面打包成图集静态文件。D1 只存“按账号隔离的个人数据”。这是“哪些东西该进数据库”的经典判断：公共不变的东西发副本，私有可变的东西存服务端。
