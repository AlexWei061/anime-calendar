网页是怎么跑起来的：从“双击打开”到“前后端对话”

你双击 index.html 能看网页，但为什么番剧日历要 npm run dev 启动？这一章把浏览器、HTTP、前后端、数据库这些“黑话”翻译成竞赛选手听得懂的话。

原理 阶段一 · 补地基 预计 40～50 分钟 前置：第 01 章

1浏览器是什么：三件套并行的“解释器”

浏览器就是一个能运行“网页程序”的运行时，它同时读懂三种语言，各管一摊：

HTML

内容（骨头）

页面里有什么：标题、按钮、输入框、链接。它只负责“结构”，不负责好看。

CSS

长相（皮肤）

长什么样：颜色、间距、圆角、布局。本项目集中在 app/globals.css。

JS

行为（肌肉）

干什么：点击后跳转、弹出详情、发请求改数据。第 01 章刚学的那门语言。

类比：HTML 是 struct 里声明了哪些字段（内容结构）；CSS 是给这些字段渲染时的格式（显示样式）；JS 是操作这些字段的逻辑（行为）。三者不是先后执行，而是同时加载、互相配合——浏览器一边解析 HTML 搭骨架，一边读 CSS 上色，一边跑 JS 加行为。

2HTML 骨架与常用标签（CSS 一句话带过）

一个网页文件的最小骨架长这样：

index.html 最小骨架
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <title>页面标题</title>
</head>
<body>
  <h1>大标题</h1>
  <p>一段文字，<a href="style.css">这是个链接</a></p>
</body>
</html>

标签（tag）就是一对尖括号里的名字：<p>…</p> 是“段落”，<h1>…</h1> 是“一级标题”。大多数标签成对出现，中间夹内容。常用标签就这几个：

标签作用备注
<h1>～<h6>标题，数字越小越重要页面主标题用 h1
<p>段落文字本文每个自然段都是它
<a href="...">链接，href 是要跳的地址点它跳到另一页
<div>无意义的“盒子”，用来分组布局网页里满屏都是它
<button>按钮“提交”“追番”都是它
<input>输入框登录框、查询框

尖括号里的 href、class、id 叫属性，给标签附加信息。CSS 两句话带过：选择器 .class（点号）/#id（井号）用来“选中哪些元素”；盒模型指每个元素都是“内容 + 内边距 + 边框 + 外边距”四层盒子。本项目样式都在 app/globals.css，先知道存在即可，第 03 章再细看。

3DOM 树：浏览器把 HTML 变成一棵树

浏览器读完 HTML，会把它解析成一棵树——这就是 DOM（Document Object Model，文档对象模型）。每个标签是树上的一个节点，嵌套关系就是父子关系。

概念示意 标签嵌套 → 树
body
 ├─ h1  "大标题"
 └─ div
     ├─ p  "一段文字"
     └─ button  "点我"
类比：这和竞赛里把 (1+2)*3 解析成表达式树一模一样——* 是根，左子树是 +。只是这里树上的节点不是运算符，而是标签和文字。

重点来了：JS 通过 DOM API 操作这棵树，就能“改页面”。你看到的“点击后弹详情”“进度条变长”，本质都是 JS 找到某个节点、改它的内容或样式：

Console 里可试 用 DOM API 改页面
const h1 = document.querySelector("h1");   // 在树里找到第一个 h1 节点
h1.textContent = "改了标题";                // 改它的文字，页面立刻变

const btn = document.querySelector("button");
btn.addEventListener("click", () => alert("被点了")); // 给节点挂一个点击行为

你不需要背这些 API——记住“页面 = 一棵树，JS 可以增删改查树上的节点”就够。React（第 03 章）会把这套手动操作再包一层，让你改“状态”而不是手动改节点。

4HTTP：浏览器和服务器之间的“评测协议”

核心类比（务必记住）：你给 OJ 交代码，本质是：你发请求（代码 + 题目号）→ 评测机处理 → 返回响应（AC / WA / CE / TLE）。HTTP 就是浏览器和服务器之间这套“评测协议”：浏览器发请求，服务器回响应，双方都按固定格式来。

一个 请求（request） 由四部分组成：方法（你想干什么）+ URL（对哪个资源）+ 头部（附加信息，如登录凭证）+ 可选的正文（比如要提交的数据）。方法对应“增删改查”：

方法含义项目里的例子
GET读数据读我的追番列表
POST新建注册、登录
PUT整体替换整表保存我的追番列表
DELETE删除删除会话（退出登录）

一个 响应（response） 最关键是开头三位数的状态码——就像评测结果：

状态码含义对 OJ 的类比
200成功AC
301资源搬走了，去新地址—（跳转）
400你发的参数格式不对CE / 格式错误
401未登录（没带会话）—（本项目 API 常返回它）
404请求的资源不存在题目编号不存在
409与当前状态冲突—（重复提交等）
500服务器自己出错评测机挂了

响应正文里放的数据，绝大多数是 JSON——一种跨语言的纯文本数据格式，就是“Python 的 dict 写成字符串”，键值对、可以嵌套数组。任何语言都能解析它，所以浏览器、服务器、数据库之间用 JSON 交流。你会在本项目 app/api/ 里看到满屏的 Response.json(...)：

响应正文示例 JSON
{ "animeIds": ["yuc-1", "history-2025-3"] }

你也能用 curl 手动发一个请求、亲眼看看响应（和 OJ 用命令行交题一个思路）：

终端 手动发请求
curl -i https://anime-calendar.example.com/api/anime-selections
# 响应头第一行就是状态码，如 HTTP/1.1 401 Unauthorized（未登录）
认路诀窍：本项目的 API 路径和文件路径一一对应——app/api/anime-selections/route.ts 处理的就是 /api/anime-selections 这个 URL，app/api/auth/login/route.ts 处理 /api/auth/login。想找某个接口的逻辑，顺着 URL 找同名文件夹即可。

小测：沿用“交代码给 OJ”的类比，HTTP 状态码 404 最接近下面哪种情况？

404 Not Found 的意思是“你请求的资源不存在”——URL 打错、接口路径写错、资源被删时出现。类比 OJ，就是你提交的题目编号不存在。AC 对应 200，CE/参数错对应 400，超时没有完全对应但接近 504（网关超时）。

5JSON、Cookie、前后端与数据库的分工

JSON 就三条规则：花括号包对象、方括号包数组、键值对用冒号。值可以是字符串、数字、布尔、null、或再嵌套对象/数组：

一部番的 JSON 键值对 + 嵌套
{
  "id": "yuc-1",
  "title": "某番",
  "episodes": 12,
  "following": true,
  "staff": { "director": "某人" }
}
类比：JSON ≈ Python 的 dict/list 组合的“文本化”。你用 json.loads() 把字符串变回 dict；浏览器里 JS 用 res.json() 干同一件事（第 01 章见过）。

Cookie 一句话：服务器让浏览器贴在身上的“名牌贴纸”——登录后服务器在响应里发一块小数据（比如会话令牌），浏览器存下来，之后每次请求自动带回去，服务器一看就知道“这是谁”。本项目第 08 章会用它做登录态。现在只需记住：HTTP 本身不记人，靠 Cookie 认人。

那么一个“追番”动作，三台“机器”怎么分工？

一句话分工：浏览器负责“画”和“交互”，Worker 负责“处理请求 + 把关”，D1 负责“长期记住数据”。注意番剧排期（data/）是打包进代码的静态数据，不在数据库里；数据库只存你的账号、追番、已看。

小测（多选）：关于本项目浏览器 / Worker / D1 的分工，哪些说法正确？

正确分工：浏览器画界面（A 对），Worker 处理请求并读写数据库（C 对）。数据库不渲染界面（B 错）；番剧排期是打包进代码的静态数据，数据库只存个人数据（D 错）。

小测：JSON 最准确的描述是？

JSON 是数据格式，不是语言也不是数据库。它的语法就是“键值对 + 数组”，和 Python 的 dict/list 一一对应，任何语言都能读写，所以用来在浏览器、服务器、数据库之间传数据。

6静态网页 vs 现代应用：为什么本教程双击就能开，番剧日历不行

本教学站是纯静态的：几个 HTML + CSS + JS，浏览器直接读就行，双击 teach/index.html 就能看，不需要任何服务器。但番剧日历是现代 Web 应用，它至少需要三件静态页面没有的东西：

  1. 构建（build）：.tsx/.ts 要先编译成浏览器能跑的 JS，React 组件要打包——所以要先 npm run dev 或 npm run build。
  2. 服务器渲染 + API：登录、读追番这些必须有个服务器（Cloudflare Worker）在跑，app/api/ 里的接口才能响应。
  3. 数据库：你的账号和已看记录要永久存，得连数据库 D1。

最后拆一个 URL，你会在地址栏和代码里反复见到它：

URL 片段名称例子里的值含义
https://协议https用加密的 HTTP 通信
anime-calendar.example.com域名主机地址服务器在哪
/路径/要哪个资源
?page=mine查询参数page=mine给页面的附加参数（本项目用它切换“我的番剧”视图）

本项目里 ?page=mine、?page=stats、?page=search 就是用查询参数切换视图——这也是第 01～03 章读完你能直接读懂的细节。

7开发者工具速览：你的“单步调试 + REPL”

按 F12（Mac 是 Cmd+Option+I）打开开发者工具，三个面板对应你竞赛时已经会的东西：

Console

交互式 REPL

像 Python 的交互式解释器：直接输入 JS 表达式回车，立刻出结果。还能看到 console.log 的输出和报错。

Network

看请求/响应

列出发出的每个 HTTP 请求，点开能看到状态码、请求方法、响应的 JSON——就是第 4 节的“评测协议”实录。

Elements

看 DOM 树

把页面当前状态的 DOM 树展示出来，等于第 3 节那棵树的可视化，还能实时改。

30 秒小实验：在本页按 F12 → 切到 Console 面板 → 输入 2 + 3 回车。你会看到 5。再输入 document.querySelector("h1").textContent，会打印出本页主标题——你刚刚用 DOM API 读了一棵树的节点。

这套工具就是你以后修 bug 的“单步调试器”：第 11 章会教你怎么用它定位“为什么点了没反应”。到这里，你已经知道网页的三件套、DOM、HTTP、前后端分工了——下一章，我们看看 React 怎么把“界面 = 状态的函数”这件事变得优雅。
