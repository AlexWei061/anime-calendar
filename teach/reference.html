02 · HTTP

请求和状态码

GET

读取事实。通常不改业务数据，但读取旧已看记录时可能触发合法迁移。

POST

提交状态变化。身份来自会话，正文只描述“要改什么”。

200 / 204

请求成功；仍需确认响应数据和刷新后的永久状态。

400

输入形状或业务值非法，先查共享校验函数。

401

没有有效会话；按 Cookie → 请求 → 会话表逐跳检查。

500

服务器未按预期完成；看日志、D1 绑定和异常路径。

06 · RED LINES

项目红线

不手改生成物

历史目录、しょぼい快照、图集和映射由脚本重建。

不猜网络时刻

只有日期就保留 null，显示“时刻未定”。

不信浏览器身份

邮箱只来自 getSessionUser()。

不拆原子替换

追番删除与分批插入在同一 db.batch()。

不手写日期特例

凌晨与集数展开复用 lib/calendar.js。

不擅自推送/部署

提交、推送、发布和公开访问是不同授权。

07 · BUG REPORT

可直接复制的 Bug 记录

标题：［页面/功能］一句话描述偏差
环境：Node 版本、浏览器、URL、桌面/移动、亮/暗色
前置条件：账号状态、季度、周、番剧稳定 ID
复现步骤：1. ... 2. ... 3. ...
期望：可观察、可断言的结果
实际：截图/文本/状态码/响应正文
首次失败位置：浏览器 → API → 共享函数 → D1 → 构建
当前假设：如果 X，那么应该观察到 Y
下一条证据：能区分 X 与其他解释的最小检查
回归测试：文件名 + 边界样例
修复边界：这次明确不改什么

写法提示 “页面坏了”不是可证伪命题；“04:59 被归到自然日，而 05:00 也在自然日”才是可复现事实。
