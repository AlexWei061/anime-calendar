LESSON 02约 45 分钟浏览器 · HTTP · Cookie

网站不是一个程序，
而是一场对话

番剧日历同时运行在浏览器和 Cloudflare Worker 中；D1 只在服务器一侧。维护它的关键不是背协议，而是永远知道当前代码在哪台“机器”上执行。

THREE RUNTIMES

先把三台机器分开

浏览器

运行 React 客户端代码，处理点击、URL、localStorage、Cookie 携带和页面显示。

Cloudflare Worker

接收请求，运行 API、服务端渲染和认证逻辑，并访问云端绑定。

D1 数据库

保存账号、会话、追番和已看记录；浏览器不能直接连接它。

静态文件

番剧目录、CSS、封面图集和打包后的脚本由站点直接提供。

把浏览器看成选手电脑、Worker 看成 OJ 服务端、D1 看成评测系统数据库。选手只能提交规定格式的请求，不能直接改排行榜数据库。
权限不变量浏览器可以表达“我想修改什么”，但服务器必须独立判断“你是谁”和“这个修改合法吗”。

HTTP

请求与响应：一次明确的函数调用

可以暂时把 HTTP 请求看成一个跨机器函数调用：

Response = API(method, path, headers, body)
方法项目中的含义真实路径示例
GET读取当前状态/api/auth/me、/api/anime-selections
POST执行一次动作或创建资源/api/auth/login、/api/auth/logout
PUT把一项状态更新成指定值整表保存追番、更新已看
浏览器发出 JSON
await fetch("/api/anime-selections", {
  method: "PUT",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ animeIds }),
});
API 解析并返回 JSON
const payload = await request.json();
const animeIds = filterKnownAnimeIds(
  payload.animeIds,
  validAnimeIds,
);
return Response.json({ animeIds });

JSON 只是跨边界传输数据的文本格式。它没有 TypeScript 类型，所以服务器仍需在运行时验证。

STATUS CODES

状态码是控制流，不是装饰

状态本项目中的解释排错第一步
200读取或动作成功继续检查返回 JSON 是否符合预期
201注册成功并创建账号检查响应中的 Set-Cookie
400请求体或字段不合法检查浏览器发出的 JSON 和验证函数
401没有有效会话检查 Cookie 是否存在、携带、过期
409注册邮箱已存在这是业务冲突，不是服务器崩溃
500服务器或绑定发生异常检查 Worker 日志、D1/R2 绑定与迁移
分层不变量401 先查身份链；400 先查输入；500 才优先怀疑服务器内部或云端资源。不要一看到“请求失败”就改 React。

COOKIE VS STORAGE

Cookie 和 localStorage 都能“记住”，但权力不同

ac_session Cookieac-theme localStorage教学站进度
用途证明会话身份记住亮暗主题记住课程完成情况
自动随请求发送是，同源请求否否
JavaScript 可读否，因 HttpOnly是是
服务器信任验证哈希和过期后才信任不用于身份不用于主应用

教学站只使用以 anime-calendar-teach: 开头的 localStorage 键，不会接触主应用的 ac-theme 或 Cookie。

Cookie 像盖章的准考证：浏览器自动带上，但服务器仍要验真伪与有效期。localStorage 更像你桌上的便签，方便但不能证明身份。

DEVTOOLS

浏览器开发者工具就是 Web 的调试器

Network

请求有没有发出？方法、状态码、请求体、响应体、Cookie 和 Set-Cookie 是什么？

Application

ac_session Cookie 和 localStorage 键是否存在、域和过期时间是否合理？

Console

运行时错误和你临时打印的状态。先读第一条真正的异常和调用栈。

Elements

DOM、CSS、可访问属性是否符合预期。它证明显示结果，不证明数据源正确。

rg -n "fetch\(|Response\.json|status: 401|Set-Cookie" app
