服务器的工作，
是守住边界

后端并不只是“把数据存起来”。它要独立确认用户身份、输入合法性、写入原子性和秘密不可逆，再把明确的状态码返回浏览器。

ROUTE HANDLER

一个 API 函数的标准证明顺序

export async function PUT(request: Request) {
  const user = await getSessionUser();
  if (!user) return Response.json(
    { error: "Sign in required" },
    { status: 401 },
  );

  // 解析并验证浏览器输入
  // 使用 user.email 读写数据库
  // 返回服务器接受后的结果
}
  1. 先认证：没有可信用户就立刻 401。
  2. 再解析：JSON 可能损坏、类型错误或超出限制。
  3. 再校验：ID 必须在 allAnime 白名单；集数必须是规范单集。
  4. 最后写入：数据库操作失败返回 500，不把内部错误泄漏给浏览器。
身份不变量业务 API 使用 getSessionUser() 得到邮箱；绝不接受浏览器提交的 userEmail 作为身份。
浏览器提交的是“主张”，服务器检查后才把它变成“事实”。这像证明题不能把结论当作前提。

ATOMIC REPLACEMENT

追番整表替换为什么必须一次 db.batch()

保存追番采用“该用户整表替换”：删旧集合，再插入新集合。若删除和插入分成独立请求，插入失败会留下空集合。

await db.batch([
  db.delete(animeSelections)
    .where(eq(animeSelections.userEmail, user.email)),
  ...selectionInsertBatches(animeIds).map((batch) =>
    db.insert(animeSelections).values(
      batch.map((animeId) => ({
        userEmail: user.email,
        animeId,
      })),
    ),
  ),
]);
D1 参数约束
单条上限
最多 100 个绑定参数。
每条追番
邮箱 + ID，共 2 个参数。
安全批量
每批最多 50 个 ID。
原子性
删除和所有插入批次放进同一 batch。
原子不变量新列表要么完整替换成功，要么旧列表完整保留；不能出现“删除成功、插入失败”的中间状态。

WATCHED UNITS

日历卡可合并，持久化必须按单集

同一天先行 1–3 集可以显示为一张卡，但详情按钮和数据库记录分别表示第 1、2、3 集：

export function episodeViewUnitsForRange({
  episodeStart,
  episode,
}) {
  const units = [];
  for (let current = episodeStart; current <= episode; current += 1) {
    units.push({ episodeStart: current, episode: current });
  }
  return units;
}

validateEpisodeViewBatch 最多接受 25 项、去重并要求 episodeStart === episode。读取旧版合法范围时，API 会展开为单集并迁移。

显示层的区间压缩像 run-length encoding；数据库的单集键是规范表示。显示可以聚合，但身份与持久状态必须无歧义。

PASSWORDS & SESSIONS

密码和会话 token 是两种秘密

密码

使用带随机 salt、100000 次迭代的 PBKDF2-SHA-256。验证时重新派生并常量时间比较。

会话 token

浏览器 Cookie 持有随机明文；数据库只保存 SHA-256 哈希。泄漏数据库不能直接伪造 Cookie。

password ──PBKDF2(salt, 100000)──► password_hash
random token ─────SHA-256────────► token_hash in D1

未知邮箱登录仍使用一个 dummy PBKDF2 hash 做同类计算，避免通过响应耗时轻易枚举账号。

秘密不变量D1 中不得出现明文密码或明文会话令牌；日志和错误响应也不应泄漏它们。

COOKIE ATTRIBUTES

四个 Cookie 属性各守一道门

属性作用项目规则
HttpOnly阻止页面 JS 读取 token始终保留
SameSite=Lax降低跨站请求携带风险始终保留
Path=/整个站点 API 都可携带始终保留
Secure只通过 HTTPS 发送仅请求 URL 是 HTTPS 时添加

本地或局域网 HTTP 开发若错误地无条件添加 Secure，浏览器不会在后续 HTTP 请求携带 Cookie，于是登录响应成功而 /api/auth/me 仍 401。

MIGRATIONS

数据库修改从 schema 开始

  1. 修改 db/schema.ts。
  2. 运行 npm run db:generate。
  3. 审查新 SQL 和 Drizzle 元数据。
  4. 本地应用迁移后验证 API。
  5. 提交 schema 与迁移，绝不只提交一边。
npm run db:generate
git diff -- db/schema.ts drizzle
迁移不变量已有数据库只能通过可审计迁移从旧状态走到新状态；不要手写与 schema 不一致的 SQL，也不要提交真实资源 ID。
