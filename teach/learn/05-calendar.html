把日历当成
一道算法题

这部分最接近你的舒适区：输入是日期与排期记录，输出是一周事件和布局位置。难点来自边界定义，而不是复杂度。

DATE MODEL

先消灭“本地时区”这个隐变量

lib/calendar.js 将 ISO 日期 YYYY-MM-DD 解析到 UTC 午夜，再只使用 UTC 日期操作。这样同一测试不会因电脑时区不同而变答案。

function parseIsoDate(isoDate) {
  const date = new Date(`${isoDate}T00:00:00Z`);
  if (date.toISOString().slice(0, 10) !== isoDate) {
    throw new RangeError(`Invalid ISO date: ${isoDate}`);
  }
  return date;
}
把日期字符串看成离散整数轴上的点，而不是带本地时区的“当前电脑时间”。函数只允许合法点进入，再做加减。
日期不变量日历算法内部只接受严格 ISO 日期；跨天统一通过 addDays，不在 JSX 里手写毫秒运算。

MODULAR ARITHMETIC

周一归一化：一个取模公式

export function startOfWeek(isoDate) {
  const date = parseIsoDate(isoDate);
  const mondayOffset = (date.getUTCDay() + 6) % 7;
  return addDays(isoDate, -mondayOffset);
}

getUTCDay() 中周日是 0、周一是 1。加 6 再模 7 后，周一映射到 0、周日映射到 6；减去偏移就得到所在周周一。

手算两个样例
周一
(1 + 6) % 7 = 0，日期不变。
周日
(0 + 6) % 7 = 6，向前六天。

BROADCAST DAY

凌晨 04:59 与 05:00 是两侧

日本深夜动画常把自然日凌晨节目视为前一“放送日”。项目用 layoutBroadcast 作为唯一布局转换：

function layoutBroadcast(broadcastDate, broadcastTime) {
  const minutes = timeToMinutes(broadcastTime);
  if (minutes < 5 * 60) {
    return {
      date: addDays(broadcastDate, -1),
      time: formatTime(minutes + 24 * 60),
      broadcastDate,
      broadcastTime,
    };
  }
  return { date: broadcastDate, time: broadcastTime,
    broadcastDate, broadcastTime };
}
真实播出周历栏目内部时间显示
周四 04:59周三28:59次日 04:59
周四 05:00周四05:0005:00
单一真源calendarDateForDateTime、当前时间标线和事件布局都应复用这一语义；不能在页面里各减一次日期。

WEEK EXPANSION

eventsForWeek：从首播推导本周集数

函数契约
输入
番剧记录数组与周一日期。
输出
布局日期落在该周的定时事件。
不变量
不超过总集数，不凭空生成无时间网络事件。
复杂度
近似 O(作品数 × 集数)，当前规模足够小。

普通周播从首播信息推导每集日期；有 episodeSchedules 时按已核对的分段排期展开。最容易出错的是“先行 N 集 + 后续电视周播”：

const premiereEpisodeCount = record.premiereEpisodeCount ?? 1;
const firstScheduledEpisode =
  premiereEpisodeCount + (record.premiereKind === "network" ? 1 : 0);

const firstRegularBroadcastDate =
  record.regularBroadcastStartDateBeijing ?? calculatedDate;

若网络先行 3 集，则电视周播必须从第 4 集开始。首行还没有明确分钟时刻时，不可把 1–3 集塞进电视时段。

这像两个拼接区间：先行段覆盖 [1, N]，固定周播覆盖 [N+1, episodeCount]。两个区间既不能重叠，也不能漏掉合法集数。

DATE-ONLY EVENTS

dateOnlyEventsForWeek：知道日期，不假装知道时刻

return records
  .filter(({ premiereDateBeijing, premiereKind }) =>
    premiereKind === "network" && dates.has(premiereDateBeijing),
  )
  .map((record) => ({
    ...record,
    date: record.premiereDateBeijing,
    episodeStart: 1,
    episode: record.premiereEpisodeCount ?? 1,
  }));

这条分支让页面显示“网络配信 · 时刻未定”。null 在这里不是缺陷，而是对来源不确定性的诚实表达。

来源不变量低优先级来源只能补空值；没有可靠分钟时刻就保持 null，不能为了让时间轴好看而估算。

GREEDY LAYOUT

layoutTimelineEvents：重叠区间的贪心分道

  1. 按开始分钟排序。
  2. 将相互重叠的事件组成 cluster。
  3. 维护每条 lane 的结束时间。
  4. 把新事件放入第一条已结束的 lane；没有就新开一条。
  5. cluster 内所有事件共享最终 laneCount，据此计算宽度。
let lane = laneEnds.findIndex((end) => end <= start);
if (lane === -1) lane = laneEnds.length;
laneEnds[lane] = start + blockDurationMinutes;
这是会议室分配问题：每条 lane 是一间会议室，事件按开始时间进入第一间已空闲的会议室。
复杂度
排序
O(n log n)
查 lane
朴素 O(n²) 最坏；单日事件很少，清晰性优先。
