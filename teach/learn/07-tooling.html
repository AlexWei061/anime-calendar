工具链不是黑箱，
是一条编译流水线

你不必精通每个工具。只要知道每一步接收什么、输出什么，以及失败说明哪一层有问题，就能安全维护项目。

RUNTIME VS PACKAGE MANAGER

Node 和 npm 分别是什么

Node.js

在浏览器之外运行 JavaScript 的环境。脚本、测试、构建和本地开发服务器都靠它。

npm

读取 package.json，安装依赖并执行命名脚本。它不是 JavaScript 解释器。

Node 类似 C++ 可执行文件的运行环境；npm scripts 类似 Makefile 中命名目标，只是命令入口，不是业务代码。
版本不变量本项目要求 Node >=22.13.0。奇怪的语法或运行差异先检查 node --version。
node --version
npm --version
npm run

COMMAND PANEL

package.json 是项目命令面板

命令做什么什么时候跑
npm run dev启动可热更新的本地站点与 Cloudflare 模拟绑定交互开发与浏览器复现
npm run typecheck运行 tsc --noEmit快速检查 TypeScript 类型
npm run build由 vinext/Vite 生成 Worker 生产产物验证生产构建、发布前
npm run lint -- --ignore-pattern .worktrees检查代码规则并忽略嵌套 worktree任何代码、数据或 UI 改动后
npm testtypecheck → build → node --test tests/*.test.mjs提交或发布前的完整证明
npm run db:generate从 schema 生成 Drizzle 迁移仅数据库 schema 变化时
验证不变量npm run typecheck 通过不代表构建和行为测试通过；项目约定的数据、UI、认证改动至少还要跑 lint 与完整 npm test。

DEV VS BUILD

开发态和生产态验证不同问题

开发态
优点
快、热更新、适合 DevTools 与复现。
不能证明
最终 Worker 能成功打包，生成元数据完整。
生产构建
检查
客户端、RSC、SSR、Worker ESM 和静态资源。
输出
dist/ 等生成物，不手工编辑。

npm test 先 build，是因为部分测试会导入构建后的 Worker 并检查服务端 HTML。只跑源文件单元测试会漏掉打包边界。

BUILD PIPELINE

源码如何成为 Cloudflare Worker

  1. Next/React 源码app/ 描述页面与 API。
  2. vinext把 Next App Router 语义接入 Vite 构建环境。
  3. Vite分析模块、分离客户端/RSC/SSR 环境并打包。
  4. Cloudflare 插件提供本地 Worker、D1、R2 和兼容标志。
  5. Sites 插件把 .openai/hosting.json 与 drizzle/ 复制进部署包。
  6. worker/index.ts处理图片优化路径，其余请求交给 vinext handler。
sed -n '1,220p' vite.config.ts
sed -n '1,220p' worker/index.ts
sed -n '1,220p' build/sites-vite-plugin.ts
像编译器多阶段流水线：前端源码不是直接丢给 CPU，而是经过分析、变换、链接和目标平台适配。

TESTS

把“对拍”变成能永久重跑的断言

项目使用 Node 内置测试运行器，不依赖 Jest。测试按职责分组：

纯函数测试

calendar.test.mjs、搜索、统计、校验。输入输出明确，运行最快。

数据审计

anime-data.test.mjs 检查目录数量、来源、封面与特殊排期。

存储源码约束

检查 API 是否认证、批量是否原子、schema 与迁移是否存在。

渲染后 HTML

rendered-html.test.mjs 检查真实构建产物中的结构与无障碍语义。

node --test tests/calendar.test.mjs
node --test --test-name-pattern="04:59" tests/calendar.test.mjs
node --test tests/rendered-html.test.mjs
测试不变量测试验证用户可见行为和数据约束；不能为了让测试通过而放松认证、校验或无障碍语义。

ERROR TRIAGE

命令失败意味着什么

失败位置通常说明先做什么
typecheck类型、导入、可空值或签名不一致读第一条项目源码错误
build服务端/客户端边界、目标平台、打包导入问题看失败发生在哪个环境阶段
单元测试行为或约束不符合断言只重跑对应测试并查看实际/期望值
lint代码质量规则或潜在 React 问题定位文件，不格式化无关代码
浏览器运行HTTP、状态或真实交互问题用 DevTools 沿数据流取证
