TASK 04 · PERSONAL DATA

修追番列表或
逐集已看状态

同一功能跨过三层：React 的即时反馈、API 的身份与输入边界、D1 的永久事实。刷新后丢失，通常说明只修到了第一层。

成功标准

  • 未登录请求返回 401，服务器从会话取得邮箱，浏览器不能声明用户身份。
  • 追番 ID 去重并过滤到 allAnime 白名单，整表替换仍是原子操作。
  • 每批最多 50 个追番 ID，删除与全部插入位于同一次 db.batch()。
  • 已看记录按 animeId + episodeStart + episode 唯一，只接受规范单集。
  • 连播卡可一次操作多集，但数据库最终保存独立单集；刷新后与乐观状态一致。
个人数据不变量客户端可以先显示结果，但只有认证后的服务器写入才是永久事实。

先读这些文件

  • app/page.tsx登录态加载、乐观更新、失败回滚和卡片交互。
  • app/api/anime-selections/route.ts追番读取、白名单过滤、分批和原子替换。
  • app/api/anime-episode-views/route.ts单集读写和旧范围记录迁移。
  • lib/anime-selections.js稳定 ID 的去重与白名单。
  • lib/anime-episode-views.js规范单集键、校验、展开和乐观更新纯函数。

最小修改顺序

  1. 把现象分成“点击后立刻错”“API 返回错”“刷新后才错”，记录请求与响应。
  2. 用稳定番剧 ID 和具体集数写失败测试，不用标题作身份。
  3. 先检查共享纯函数是否产出规范单元，再检查 React 是否调用它。
  4. 确认 API 首先认证，邮箱只来自 getSessionUser()，输入通过白名单/集数校验。
  5. 检查 D1 操作的原子边界、参数数量和唯一键，只修导致失败的最小一层。
  6. 验证成功、401、非法输入、写入失败回滚和刷新重载五条路径。

回归测试

追番

重复/未知 ID 被过滤；超过 50 项分批但整体成功或整体失败。

已看

连播范围展开为独立单集键，任意范围与越界集数被拒绝。

迁移

合法旧范围读取时展开为单集，随后与新格式一致。

回滚

乐观更新失败后恢复旧状态并显示可理解的错误。

node --test tests/anime-selections.test.mjs tests/anime-episode-views.test.mjs

验证

npm run lint -- --ignore-pattern .worktrees
npm test
git diff --check
git diff -- app/page.tsx app/api lib/anime-selections.js lib/anime-episode-views.js

手工验证要包含一次刷新和另一个浏览器/设备读取，否则只能证明 UI 改了，不能证明持久化正确。

停止并确认

这些改动会碰用户数据，先确认：
  • 准备改变整表替换或单集唯一键语义；
  • 迁移可能删除或合并现有记录；
  • 为了方便准备信任浏览器传来的邮箱；
  • 打算先删除旧数据、再进行可能失败的独立插入；
  • 测试只能靠放宽白名单或认证才能通过。
