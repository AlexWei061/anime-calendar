TASK 02 · SCHEDULE

修日期、时刻、
集数或先行配信

先判断错的是来源事实还是共享算法。单条作品错误通常从数据取证开始；一批凌晨节目同时错误才优先查 lib/calendar.js。

成功标准

  • 修改后的字段有可靠来源 URL 和正确 *Source 审计标记。
  • 来源优先级保持 YUC → AniList → しょぼい → 估算或 null。
  • 未公布分钟时刻的网络首播仍在“时刻未定”区域，不被猜成电视时刻。
  • 先行 1–N 集只出现一次，固定周播从 N+1 集开始。
  • 00:00–04:59 使用前一天栏目与“次日”显示；05:00 留在自然日。
排期不变量低优先级来源只能补空值；显示日期变换由共享算法完成，原始播出事实不因布局而篡改。

先读这些文件

  • data/anime.js季度入口、当前 2026 年 7 月 YUC 目录与 allAnime。
  • lib/calendar.js每周展开、无时刻事件、凌晨布局与时间轴。
  • tests/calendar.test.mjs边界、先行多集、同刻布局与周导航回归。
  • tests/anime-data.test.mjs目录数量、来源字段、特殊作品和封面约束。

历史 data/yuc-history-<year>.js 和 data/syoboi-history-<year>.js 是生成文件，不直接编辑。

最小修改顺序

  1. 记录作品稳定 ID、当前字段、错误表现和权威来源证据。
  2. 判断是当前季手工目录、历史生成管线，还是共享算法问题。
  3. 先写会失败的用户可见断言：日期、时间标签、集数范围或数据来源。
  4. 若 YUC 详情有“M/D先行N话”，同时填写 premiereDateBeijing、premiereKind、premiereEpisodeCount、regularBroadcastStartDateBeijing。
  5. 只修改负责错误的字段或函数；保持 catalogCount === anime.length。
  6. 封面或生成目录变化时按数据管线手册重建，不手工补产物。

回归测试

涉及“先行多集 + 后续周播”必须同时证明两件事：

// 先行日：显示第 1-N 集，且没有虚构时间
// 首个固定周播日：从第 N+1 集开始

单条数据

断言 ID、日期、总集数、来源 URL 和审计字段。

周展开

断言目标周只出现期望集数，不重复、不越界。

凌晨阈值

04:59 与 05:00 成对出现，证明两侧语义。

无时刻

dateOnlyEventsForWeek 包含，eventsForWeek 不虚构。

验证

node --test tests/anime-data.test.mjs tests/calendar.test.mjs
npm run lint -- --ignore-pattern .worktrees
npm test
git diff --check

若修改封面，完整验证前还要运行 npm run convert:covers-webp 和 npm run generate:cover-sprites。

停止并确认

不要自行推断：
  • 两个来源给出冲突日期或不同“首播”定义；
  • 只有日期，没有分钟时刻；
  • 作品身份映射可能一对多或标题相似；
  • 修正会重写整年生成目录或大量封面；
  • 现有测试表明代码语义与用户描述并不一致。
