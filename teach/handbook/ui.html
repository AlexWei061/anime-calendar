TASK 01 · UI

修改文案、样式
或页面交互

先判断是“只显示不同”还是“行为也不同”。前者通常只动 CSS；后者才进入 React 状态、事件与路由。

成功标准

  • 目标文案、尺寸、颜色或交互在指定页面准确变化。
  • 亮色和暗色都使用同名设计 token，没有组件硬编码颜色。
  • 桌面时间轴与小于等于 860px 的移动议程行为一致。
  • 键盘、焦点、按钮语义、aria-pressed 与浏览器前进/后退未退化。
  • 追番统计、查询卡和日历卡的尺寸边界没有互相污染。
UI 不变量视觉变化不应复制排期算法；交互变化不应绕过 URL、认证或服务器持久化。

先读这些文件

  • app/page.tsx状态、派生值、事件、四个页面分支、dialog 与移动/桌面渲染。
  • app/globals.css主题 token、桌面时间轴、查询/统计卡和 860px 断点。
  • app/layout.tsx元数据与首屏前主题脚本；通常不因普通 UI 改动而动。
  • tests/rendered-html.test.mjs渲染后结构、无障碍按钮、导航和主题约束。
rg -n "activePage|dialog|aria-pressed|timeline|@media" app/page.tsx app/globals.css tests/rendered-html.test.mjs

最小修改顺序

  1. 写下桌面、移动、亮色、暗色和键盘行为的成功标准。
  2. 只改文案时先定位唯一 JSX 文本；只改视觉时优先找到已有选择器与 token。
  3. 行为变化先找到对应 state、派生值、effect 和 handler，不在 JSX 中复制逻辑。
  4. 若是 bug，先在 rendered-html.test.mjs 或对应纯函数测试加入失败断言。
  5. 做足以满足断言的最小修改，清理由本次修改造成的无用变量或 import。
  6. 检查 CSS 选择器只命中目标组件，特别区分查询、统计、桌面卡与移动议程。

回归测试

结构

断言目标按钮、标题、dialog 或卡片仍存在且语义正确。

路由

页面切换仍写入 ?page=，popstate 能恢复。

响应式

移动端保留单日选择器和议程，不把桌面 sticky 规则带过去。

主题

新增颜色来自 token，暗色定义同名覆盖。

node --test tests/rendered-html.test.mjs
node --test --test-name-pattern="目标行为关键词" tests/rendered-html.test.mjs

验证

npm run lint -- --ignore-pattern .worktrees
npm test
git diff --check
git diff -- app/page.tsx app/globals.css tests/rendered-html.test.mjs

视觉调整还应在真实浏览器分别检查宽屏和窄屏；未获得浏览器测试授权时，明确交付需要人工检查的视口。

停止并确认

遇到以下情况不要猜：
  • “更好看”存在多个明显方向，需要用户选择视觉方案；
  • 需求会改变已批准的交互，例如移除移动议程或改 URL 模型；
  • 现有未提交改动与同一 CSS/JSX 区域重叠；
  • 看似样式问题，证据却显示数据或 API 已经错误。
