TASK 03 · DATA PIPELINE

更新历史目录、
来源数据或封面

这是一条有依赖顺序的生成流水线。把它看成数学计算：原始数据是输入，生成文件是中间结果，图集是最终产物。

成功标准

  • 来源逐字段合并，优先级仍为 YUC → AniList → しょぼい → 估算或 null。
  • 历史目录、しょぼい快照、图集和映射均由脚本生成，没有手工修改产物。
  • 中文名与封面仍来自 YUC；已有高优先级字段不被低优先级来源覆盖。
  • 稳定 ID、catalogCount、封面逻辑键与来源审计字段通过测试。
  • 部署资源仍是图集，没有恢复成大量独立封面。
生成不变量只编辑输入或生成器；产物必须能由记录下来的命令重新得到。

先读这些文件

  • scripts/generate-anilist-pilot.mjs第一层原始首播、时刻和集数资料。
  • scripts/generate-yuc-history-pilot.mjs合并 YUC、AniList 和已有しょぼい快照。
  • scripts/generate-syoboi-history.mjs以当前目录做身份匹配，生成电视排期快照。
  • scripts/convert-covers-to-webp.mjs把中间封面转换为无损 WebP。
  • scripts/generate-cover-sprites.mjs生成 4×10 图集和映射。

最小修改顺序

  1. 确定年份、来源和要修字段，先保存权威页面证据。
  2. 只补 AniList/YUC 时：先生成 AniList，再生成一次 YUC 历史目录。
  3. 重新核对电视排期时：AniList → 第一次 YUC 目录 → しょぼい快照 → 第二次 YUC 目录。
  4. 检查生成 diff：身份匹配、字段来源、数量和封面逻辑键；异常时先停。
  5. 有封面变化时再运行 WebP 转换 → 图集生成，不调换顺序。
  6. 最后跑数据测试、lint 与全套测试，只提交本次年份相关输入和产物。
npm run generate:anilist -- <year>
npm run generate:yuc-history -- <year>
npm run generate:syoboi-history -- <year>
npm run generate:yuc-history -- <year>
npm run convert:covers-webp
npm run generate:cover-sprites

回归测试

身份

ID 全局唯一且稳定，不能因标题翻译变化创建“新作品”。

来源

*Source 与实际来源一致，高优先级值未被覆盖。

目录

catalogCount === anime.length，必填字段齐全。

封面

逻辑键能映射到存在的图集坐标。

验证

node --test tests/anime-data.test.mjs tests/cover-sprites.test.mjs
npm run lint -- --ignore-pattern .worktrees
npm test
git diff --check

生成脚本需要联网时，先小范围运行一个年份，不在结果尚未审阅时批量重写全部历史。

停止并确认

出现这些信号就暂停：
  • 身份映射不唯一，两个来源似乎不是同一部作品；
  • 生成 diff 波及目标年份之外的大量条目；
  • 来源值互相冲突或页面不可访问；
  • 脚本准备覆盖尚未提交的生成产物；
  • 图集数量、坐标或部署体积异常跳变。
