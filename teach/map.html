PROJECT MAP

不要从 2111 行的页面开读，
先建立地图

看懂项目不是记住每一行代码，而是能回答三个问题： 这份信息从哪里来？谁加工它？谁有权修改它？

总不变量 静态排期留在代码里；个人状态经过认证 API 进入 D1；浏览器不能替服务器决定用户身份。

EIGHT LAYERS

八层，不是八种技术

每层都只做一类事。点击卡片展开“输入—输出—依赖—故障”。

L1 浏览器URL · Cookie · localStorage · DevTools

职责：接收点击、保存设备偏好、携带 Cookie、显示服务器响应。

输入
用户操作、HTML/CSS/JS、HTTP 响应
输出
请求、页面状态、可见界面

项目入口：?page=mine、localStorage ac-theme、ac_session Cookie。

常见故障：URL 状态不同步、Cookie 没有被保存、旧本地状态影响复现。

↓
L2 静态番剧数据事实、来源与生成结果

职责：描述有哪些作品、哪天首播、几点播、多少集、封面在哪里。

输入
YUC、AniList、しょぼい快照
输出
统一季度目录与封面映射

核心文件：data/anime.js、生成的 data/yuc-history-<year>.js、data/cover-sprites.js。

常见故障：手改生成物、来源优先级反了、给未公布的网络配信猜时间。

↓
L3 纯算法层输入固定，输出可测试

职责：把目录变成每周事件，并完成日期、集数、搜索、统计和校验。

输入
番剧记录、周一日期、已看集合
输出
事件、布局位置、合法单集单元

搜索这些函数：eventsForWeek、dateOnlyEventsForWeek、layoutTimelineEvents、episodeViewUnitsForAnime。

核心文件：lib/calendar.js、lib/anime-episode-views.js。

常见故障：04:59/05:00 边界、先行 N 集与后续周播重复、连播范围没有拆成单集。

↓
L4 React 状态与界面UI = f(state)

职责：维护当前页、周、季度、用户、追番和已看状态，并把计算结果渲染为桌面或移动界面。

输入
静态目录、算法结果、API 响应、用户操作
输出
JSX 界面与下一次请求

核心文件：app/page.tsx。先搜索 useState、useEffect、fetch( 和最终 return，不要从第一行顺读到最后。

常见故障：乐观更新失败后未回滚、桌面和移动端行为不一致、React 状态与 URL 状态脱节。

↓ HTTP ↑
L5 API 边界认证 · 校验 · 状态码

职责：接收 JSON，请服务器确认用户和数据合法性，再读写持久状态。

输入
HTTP 方法、Cookie、JSON 请求体
输出
JSON、状态码、Set-Cookie

核心文件：app/api/anime-selections/route.ts、app/api/anime-episode-views/route.ts。

常见故障：忘记认证、相信浏览器提交的任意 ID、先删除再单独插入导致旧数据丢失。

↓
L6 认证与安全密码哈希 · 会话哈希 · Cookie

职责：证明请求属于哪个账号，并确保密码和会话令牌不以明文进入数据库。

输入
邮箱、密码或 ac_session
输出
服务器可信的用户对象或 401

核心文件：app/auth.ts、lib/auth.js；搜索 getSessionUser、PBKDF2 和 SHA-256。

常见故障：本地 HTTP 错误使用 Secure、Cookie 未携带、会话过期或数据库迁移缺失。

↓
L7 D1 数据库用户、会话、追番、已看

职责：永久保存每个账号的个人状态；不保存番剧排期目录。

输入
经过认证与校验的查询或写入
输出
行记录、约束错误、事务结果

核心文件：db/schema.ts、db/index.ts、drizzle/。

常见故障：绑定 DB 不可用、schema 与迁移不同步、批量参数超过 D1 限制。

↓ 打包与运行
L8 构建与部署vinext · Vite · Worker · Sites

职责：把 Next/React 源码变成 Cloudflare Worker 可运行的 ESM，并携带 Sites 元数据和迁移。

输入
源代码、静态资源、逻辑绑定声明
输出
Worker 产物与部署包

核心文件：worker/index.ts、vite.config.ts、build/sites-vite-plugin.ts。

常见故障：Node 构建时顶层导入 Cloudflare 专用模块、真实资源 ID 进入仓库、发布的不是刚验证的提交。

FIRST REPOSITORY TOUR

第一次读项目，按这个顺序

  1. 先读 README 和 AGENTS.md知道产品目标、不能破坏的约定和验证命令。
  2. 再读小而纯的 lib/从函数输入输出建立信心，优先看 calendar.js 的测试。
  3. 再看 API + schema把 HTTP、认证和数据库连成一条线。
  4. 最后拆解 app/page.tsx按 imports → types → state → derived values → effects → handlers → JSX 分段读。
进入系统课程 按任务反查文件
