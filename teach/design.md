## 1. 目标与成功标准

为一名具备 C++、Python 基础语法和信息学竞赛经验，但缺少现代 Web 工程经验的数学系学生，制作一套可以长期使用的项目教学与维护网站。

网站完成后，学习者应当能够：

1. 解释浏览器、React 页面、API、Cloudflare Worker、D1 和静态番剧数据各自负责什么。
2. 沿着真实数据流找到一项功能涉及的文件，而不是在仓库中盲目搜索。
3. 读懂本项目常见的 JavaScript、TypeScript、React、异步请求和 Drizzle 代码。
4. 按固定流程修改界面、排期、认证、个人数据和数据库结构。
5. 把 bug 当作反例，先复现和分层定位，再写回归测试并完成最小修复。
6. 知道哪些文件可以手改、哪些是生成物、哪些操作可能破坏数据或发布状态。
7. 在半年后仍能把网站当作任务手册、排错入口和命令速查表使用。

## 2. 非目标

- 不制作通用的 JavaScript、React 或前端开发大全。
- 不在教学任务中修改 `app/`、`lib/`、`data/`、`db/`、测试、部署配置或线上状态。
- 不复制或改写 `teach__/` 的页面；该目录作为另一份独立作品完整保留。
- 不引入框架、构建步骤、第三方字体、远程脚本、图片或网络依赖。
- 不在本次任务中发布教学站或主项目。

## 3. 核心体验：一套内容，两条入口

首页提供两条同等重要的路线。

### 3.1 系统学习

适合第一次建立完整心智模型。课程按依赖关系逐步展开：

1. C++ / Python 到 JavaScript / TypeScript
2. 浏览器、HTTP、Cookie 与前后端边界
3. React：`UI = f(state)`
4. 项目全景与真实数据流
5. 日历、集数和时间轴算法
6. API、D1、Drizzle 与安全边界
7. Node、构建、测试与 Cloudflare Worker
8. 从需求到发布的完整维护闭环

### 3.2 立即做事

适合带着现实任务进入网站。手册按目标而非技术名词组织：

1. 修改文案、颜色或界面布局
2. 修正一部番剧的日期、时间或集数
3. 更新历史数据与封面图集
4. 排查追番和已看记录
5. 排查注册、登录、Cookie、密码或头像
6. 修改数据库结构和迁移
7. 验证、提交、发布与回滚判断

两条路线引用相同的知识节点。例如，“HTTP 状态码”既出现在系统课程，也会从“登录后仍提示未登录”的排错任务进入，不维护两份互相漂移的解释。

## 4. 信息架构

网站由以下区域组成：

### 4.1 首页 `index.html`

- 用一句话说明项目和教程的目标。
- 展示两条学习入口。
- 展示项目主链：`data → lib → app/page.tsx → app/api → D1`。
- 显示总体进度、最近学习节点和常用任务入口。
- 标出教程依据的代码基线，提醒代码变化后重新核对。

### 4.2 项目地图 `map.html`

- 按浏览器、静态数据、纯算法、React、API、认证、数据库、构建部署八个节点展示项目。
- 点击节点展开职责、输入、输出、依赖、核心文件、常见故障和阅读顺序。
- 提供三条可高亮的数据流：显示一周日历、保存追番、登录并恢复会话。
- 图形使用语义化 HTML 和 CSS，不使用模型生成的 SVG。

### 4.3 系统课程 `learn/`

八个模块各用一个页面。每个知识点固定采用四层结构：

1. 一句话直觉
2. C++、Python、算法或数学类比
3. 当前项目的真实代码与文件定位
4. 小练习与答案解释

### 4.4 维护手册 `handbook/`

每个任务页面采用统一结构：

1. 成功标准
2. 先读哪些文件
3. 数据或请求如何流动
4. 哪些文件能改、哪些不能手改
5. 最小修改顺序
6. 需要补充的回归测试
7. 验证命令
8. 常见陷阱和停止条件

### 4.5 Debug 实验室 `lab/`

首批提供三个项目专属案例：

1. 凌晨节目显示在错误日期
2. 登录成功后页面仍显示未登录
3. 已看状态刷新后消失或连播集数不正确

实验流程为“现象 → 可选证据 → 故障层判断 → 最小复现 → 回归测试 → 修复边界”。错误选择会给出解释，允许随时重置，不永久惩罚学习进度。

### 4.6 速查页 `reference.html`

- 术语中英对照
- HTTP 状态码与常见含义
- npm 命令与适用时机
- 文件与职责反查
- 数据更新顺序
- 数据库与发布红线
- 按错误信息或症状查找入口

## 5. 个性化教学原则

### 5.1 用已有知识搭桥

- React 组件：状态到界面的函数。
- state：决定输出的可变参数。
- effect：函数外部世界的同步动作。
- API：长期运行、能接收多次提交的评测接口。
- 类型检查：比运行前样例更早发现一类错误。
- bug：推翻“程序总是正确”的反例。
- 回归测试：把反例永久加入测试集合。
- 数据校验与认证边界：程序必须保持的不变量。

### 5.2 先理解边界，再看语法细节

讲解函数时先回答：输入是什么、输出是什么、依赖什么、必须保证什么。只有这些问题需要时，才补充语法。

### 5.3 真实代码优先

课程引用当前仓库中的文件、函数名和可搜索关键词。避免使用容易漂移的固定行号；需要定位时给出 `rg` 搜索词。

### 5.4 逐步揭示

默认先显示直觉和数据流。精确类型、异常分支、安全原因和完整代码放在可展开区域，避免第一次阅读时被细节淹没。

## 6. 核心交互

- 全站目录和面包屑导航。
- 本地全文索引，可按概念、文件名、任务和症状搜索。
- 学习进度和任务清单，可勾选并持久化。
- 深色与浅色主题。
- 代码与命令一键复制；失败时保持原文可手动选择。
- 项目地图节点展开与数据流高亮。
- 选择题、路径判断题和 Debug 分支实验。
- 演示模式，将当前页面的主要章节逐屏展示。
- 浏览器前进、后退和普通链接正常工作。

所有持久状态只保存在带 `anime-calendar-teach:` 前缀的 `localStorage` 键中，不接触主应用的 `ac-theme`、Cookie 或 API。

## 7. 技术结构

网站采用静态多页结构：

```text
teach/
├── design.md
├── index.html
├── map.html
├── reference.html
├── learn/
│   ├── 01-language.html
│   ├── 02-web.html
│   ├── 03-react.html
│   ├── 04-architecture.html
│   ├── 05-calendar.html
│   ├── 06-backend.html
│   ├── 07-tooling.html
│   └── 08-maintenance.html
├── handbook/
│   ├── ui.html
│   ├── schedule.html
│   ├── data-pipeline.html
│   ├── personal-data.html
│   ├── auth.html
│   ├── database.html
│   └── release.html
├── lab/
│   ├── index.html
│   ├── midnight.html
│   ├── session.html
│   └── watched.html
├── search-index.js
├── app.js
└── styles.css
```

正文写在语义化 HTML 中，核心阅读不依赖 JavaScript。`app.js` 只负责渐进增强：共享导航、搜索、进度、主题、复制、地图和实验。`search-index.js` 保存页面元数据、关键词和摘要，不复制长篇正文。

所有资源使用相对路径，因此可直接双击 `teach/index.html` 使用。站点不使用 `fetch()` 加载本地文件，避免 `file://` 环境的跨源限制。

## 8. 视觉设计

视觉主题是“数学笔记 × 工程控制台”：

- 米白纸张和墨蓝正文为默认主题。
- 樱花粉表示当前路径或主要动作。
- 青绿色表示通过、可安全修改或数据流成功。
- 琥珀色表示需要验证。
- 红色只用于危险操作、边界破坏或失败状态。
- 背景使用轻微坐标纸网格；代码和命令使用系统等宽字体。
- 文件路径、函数名、命令、状态码和数据表拥有不同且稳定的视觉标记。
- 桌面使用横向数据流和双栏讲解；窄屏改成纵向路径，交互目标不小于 44px。

动画只用于状态变化和路径高亮，并遵循 `prefers-reduced-motion`。

## 9. 无障碍与降级

- 所有功能可用键盘操作，并保持明显的焦点样式。
- 颜色不是唯一的信息载体；状态同时使用文字或符号。
- 折叠区域使用原生 `details`，按钮使用正确语义和 `aria` 属性。
- JavaScript 失效时，正文、目录、普通链接和练习答案仍可访问。
- `localStorage` 读写放在 `try/catch` 中；失败只关闭进度功能。
- 搜索无结果时提供项目地图、术语页和相近关键词建议。

## 10. 验证方案

实现完成后执行以下验证：

1. 自动检查所有 HTML 页面、相对链接、锚点和引用的真实项目路径。
2. 执行 `node --check teach/app.js` 和 `node --check teach/search-index.js`。
3. 检查不存在外部资源、绝对部署地址或对 `teach__/` 的依赖。
4. 验证主题、进度、搜索、复制、地图、实验、演示模式和历史导航的降级行为。
5. 检查桌面与窄屏布局，以及键盘焦点和 reduced-motion 样式。
6. 抽查课程中的代码、命令、函数名、数据流程和安全约束是否与当前仓库一致。
7. 运行 `npm run lint -- --ignore-pattern .worktrees` 与 `npm test`，确认新增静态站没有干扰主项目。
8. 运行 `git diff --check` 并确认 `teach__/` 没有变化。
