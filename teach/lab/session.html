CASE 02 · AUTH

登录返回 200，
下一请求却是 401

在 Mac 的 LAN HTTP 地址打开网站，登录接口说成功，但刷新后 /api/auth/me 返回 401；localhost 看起来正常。

现象

登录响应
200，正文包含用户昵称
后续请求
/api/auth/me → 401
环境差异
LAN HTTP 失败，HTTPS/某些 localhost 路径正常
未知
密码、Set-Cookie、浏览器策略还是服务端验签？

数学类比 登录成功只是链路中间命题；要证明“已登录”，还必须证明 Cookie 被浏览器接受并在下一请求中发送。

DECISION 1 / 2

假设：哪组证据最有区分力？

目标证据：定位身份链路在哪一跳第一次断开。

DECISION 2 / 2

证据、最小复现与回归测试

登录响应含 Set-Cookie: ac_session=...; Secure; HttpOnly; SameSite=Lax，但 LAN HTTP 的浏览器没有保存它。哪条回归最精确？

修复边界

最小修复在 app/auth.ts 只对 HTTPS 请求附加 Secure；保持 HttpOnly、SameSite=Lax 和 Path=/。
  • 浏览器没有保存 Cookie 时，不要先改 getSessionUser() 或 D1 查询。
  • 若 Cookie 已发送而仍是 401，当前假设被推翻，再检查令牌哈希、过期时间和会话记录。
  • 回归需覆盖登录/注册签发和退出清理，以及受保护 API。
