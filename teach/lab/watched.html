CASE 03 · PERSISTENCE

“第 1–3 集已看”
刷新后全部消失

先行三集在周历上合成一张卡。点击方框后卡片立刻变淡，但刷新页面，三集都恢复为未看。

现象

显示单元
一张“第 1–3 集”连播卡
即时状态
三集看似全部已看
刷新后
三集全部未看
未知
乐观更新、请求 payload、API 校验还是 D1 唯一键？

数学类比 区间 [1,3] 是展示压缩，不等于存储基底。系统的规范基底是三个单集向量：1、2、3。

DECISION 1 / 2

假设：先比较哪两个事实？

目标证据：判断“看起来成功”是否只有 React 乐观状态。

DECISION 2 / 2

证据、最小复现与回归测试

证据显示 UI 调用了 episodeViewUnitsForAnime 得到 1、2、3，但 POST 合并成一个范围，API 正确拒绝它。哪条回归测试最稳？

修复边界

最小修复保持展示卡可以合并，但写入必须使用 episodeViewUnitsForAnime 产生的独立单集；API 继续用 getSessionUser 决定邮箱并拒绝任意范围。
  • 先写能复现“即时成功、刷新丢失”的回归，再修 payload 组装。
  • 旧版合法范围只在读取迁移路径展开，不能重新成为新写入格式。
  • 同时测试某一集写入失败时乐观状态如何回滚，避免 UI 与服务器分叉。
